The Blobmoji build pipeline.

Extracted from the legacy fonts-rs-blobmoji build.rs so every variant crate runs the identical export: pre-rendered emoji_u*.svg artwork for GResources (full color, original artwork) plus the variant’s TTF for pixel-drawing (ab_glyph) and the font.gresource.

Glyph names come from CLDR annotation data (annotations.json + annotations-derived.json in the shared fonts-rs-emoji-metadata crate): the emoji sequence encoded in each emoji_u*.svg filename is mapped to the CLDR tts name (kebab-cased). Sequences without a CLDR name keep their raw filename stem. Emoji sequences are allocated PUA codepoints by SvgDirSource.

Unlike Noto Emoji, the vendored Blobmoji SVGs use prefixed xmlns:ns1 namespaces that must stay bound - no StripEntityNamespaces post-processing here.

CARGO_FEATURE_METADATA gates keyword/category/ordering generation (the crate’s metadata feature).
