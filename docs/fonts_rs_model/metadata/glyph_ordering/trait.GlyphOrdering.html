Expand description

Canonical ordering and grouping contract for a font family.

All data is build-time generated and returned as 'static references - implementations are meant to be backed by phf maps and static slices, so the trait is object-safe and usable as &'static dyn GlyphOrdering.

fn order_index(&self, name: &str) -> Option<u32>

Returns the canonical ordering position of a base glyph.

Variants (alternates) and unordered glyphs return None; consumers wanting variant-sort should consult GlyphOrdering::base_of for a fallback.

Source

fn group(&self, name: &str) -> Option<GroupLabel>

Returns the group label for a glyph, including variants.

Source

fn group_labels(&self) -> &'static [GroupLabel]

Returns the group labels in canonical order.

fn groups(&self) -> &'static [GlyphGroup]

Returns the groups in canonical order.

Each GlyphGroup lists glyph names in picker order with variants inlined after their base - the full layout for UIs that want a native picker view.

Source

fn base_of(&self, name: &str) -> Option<&'static str>

Returns the base glyph name for a variant (e.g. a skin-tone sequence), or None if name is a base glyph.

Source

fn alternates(&self, _name: &str) -> &'static [&'static str]

Returns the variant glyph names of a base glyph (skin tones, gender combos, …), in canonical order. Empty for glyphs without variants.

Source

fn tone_group(&self, _name: &str) -> Option<u32>

Returns the opaque variant-shape group of a glyph.

Entries sharing a tone_group have the same alternates shape, so a chosen position transfers to every base glyph in the group - this powers the classic picker feature “set default skin tone once, apply everywhere”. Returns None for glyphs without tone variants; implementations should resolve variants through their base. Defaults to None for families without tone data.

Source

fn collapse_variants(&self) -> bool

Whether consumers may collapse variants behind their base glyph. Defaults to true - families with alternates usually want the compact picker presentation.
