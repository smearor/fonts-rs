fonts-rs Documentation

Introduction

fonts-rs is a Rust workspace for integrating font families into GTK4 projects. It provides a modular framework for exporting glyphs as SVG icons, generating GResource bundles, resolving icon names to Unicode codepoints, and rendering text with software rasterization.

Architecture Overview

The workspace is organized into three layers:

  1. Generic framework - fonts-rs-model (shared types) and fonts-rs-generator (build-time pipeline)
  2. Font family crates - one crate per font family (e.g. fonts-rs-doto, fonts-rs-bravura, fonts-rs-seven-segment). The emoji families (Noto Emoji, Blobmoji) are an exception: they are split into resource, variant and umbrella crates to stay under the crates.io 10 MiB package limit - see Architecture
  3. Nerd Fonts integration - nerd-fonts-model, nerd-fonts-generator, and nerd-fonts-rs for the legacy Nerd Fonts-specific API

Features

  • Modular font family crates - each font family is a separate crate with its own build script, GResource bundle, and runtime API
  • Type-safe glyph names - GlyphName<F> phantom typing prevents mix-ups between font families at compile time
  • Variable font support - variants via Cargo features with axis-based rendering (e.g. weight, roundness)
  • GTK4 integration - GResource registration, icon name resolution, CSS providers
  • Software rendering - font loading via ab_glyph for headless rendering (see pixel-drawing)
  • Build-time code generation - phf::Map codepoint maps, Rust constants, and GResource XML generated from font files
  • Metadata generation - keywords, categories, and aliases for search functionality (e.g. Noto Emoji CLDR annotations)

Getting Started

Prerequisites

Rust

A working Rust toolchain is required. The project uses Rust Edition 2024.

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

Minimum Supported Rust Version (MSRV)

The crate declares rust-version = "1.92" in its Cargo.toml. The MSRV is verified by CI on every push and pull request.

Linux System Dependencies

The gtk feature requires GTK 4 development libraries.

Ubuntu/Debian:

sudo apt-get install -y pkg-config libgtk-4-dev libglib2.0-dev

Fedora:

sudo dnf install -y pkg-config gtk4-devel glib2-devel

Arch Linux:

sudo pacman -S pkgconf gtk4 glib2

No System Dependencies (font loading or web only)

If you only need font loading (render feature) or web CSS (web feature), no system libraries are required beyond a Rust toolchain.

From crates.io

From Source

git clone https://github.com/smearor/fonts-rs.git
cd fonts-rs

Feature Selection

Each font family crate provides the same feature gates:

# GTK4 integration (default)
fonts-rs-doto = "0.5"

# GTK4 + software rendering + embedded fonts
fonts-rs-doto = { version = "0.5", features = ["gtk", "render", "embed-fonts"] }

# Software rendering only (no GTK)
fonts-rs-doto = { version = "0.5", default-features = false, features = ["render"] }

# Variable font variant selection (Doto example)
fonts-rs-doto = { version = "0.5", features = ["bold-dot"] }

The emoji families are umbrella crates over one crate per TTF variant - a variant feature selects a whole crate, so exactly one may be active (enabling several is a compile error):

# Noto Emoji default: COLRv1 with flag emoji (color-flags)
fonts-rs-noto-emoji = "0.5"

# A different variant: disable defaults, then pick exactly one
fonts-rs-blobmoji = { version = "0.5", default-features = false, features = ["gtk", "bitmap-flags"] }

For Nerd Fonts specifically:

# GTK4 with 4.12+ APIs
nerd-fonts-rs = { version = "0.5", features = ["gtk", "v4_12"] }

# Font loading only (no GTK)
nerd-fonts-rs = { version = "0.5", default-features = false, features = ["render"] }

# Web CSS only
nerd-fonts-rs = { version = "0.5", default-features = false, features = ["web"] }

# Icon metadata (keywords & categories)
nerd-fonts-rs = { version = "0.5", features = ["metadata"] }

Quick Start

Font Family Crate (e.g. Doto)

use fonts_rs_doto::Doto;

fn main() {
    // Register GResource + install font (gtk feature)
    Doto::install().unwrap();

    // Look up a glyph by name
    if let Some(codepoint) = Doto::codepoint("doto-a") {
        println!("Glyph codepoint: U+{:04X}", codepoint.as_char() as u32);
    }
}

Nerd Fonts (nerd-fonts-rs)

use nerd_fonts_rs::NerdFonts;

fn main() {
    // Call once at startup
    nerd_fonts_rs::init().unwrap();

    // Resolve an icon name to its Unicode codepoint
    if let Some(c) = NerdFonts::codepoint("nf-fa-gamepad") {
        println!("Gamepad icon: U+{:04X}", c.as_char() as u32);
    }
}

Build Pipeline

Each font family crate follows the same build pipeline via FontBuild. Fontless icon sets (Lucide, Heroicons) use FontBuild::svg_only() + run_svg() - same artifacts, but the input is an SVG directory and change detection relies entirely on extra_hash components:

flowchart TD
    Font["Font file (TTF/OTF)"] --> Hash["FNV-1a hash"]
    Hash --> Check{"Hash changed?"}
    Check -->|Yes| Export["Export glyphs to SVG"]
    Check -->|No| Skip["Skip export"]
    Export --> Meta["metadata.json"]
    Export --> SVGs["scalable/glyphs/*.svg"]
    Export --> XML["icons.gresource.xml"]
    Meta --> Codegen["Code generation"]
    XML --> GResource["GResource compilation"]
    Codegen --> Codemap["$OUT_DIR/codemap.rs (phf::Map)"]
    Codegen --> Icons["$OUT_DIR/icons.rs (constants)"]
    Codegen --> Variant["$OUT_DIR/variant.rs (variant info)"]
    GResource --> Compiled["icons.gresource (binary)"]
    Skip --> Codegen

Hash-Based Change Detection

FontBuild computes an FNV-1a hash of the font file and stores it in resources/.hash. On subsequent builds, the hash is compared to determine whether re-export is needed. For variable font variants, extra_hash() adds the variant name to the hash, forcing re-export when the active variant changes even if the font file is unchanged.

Code Generation

The default code generation produces three files in OUT_DIR:

  • codemap.rs - phf::Map<char, &str> (codepoint → glyph name) and phf::Map<&str, char> (glyph name → codepoint)
  • icons.rs - pub const strings for each glyph name
  • variant.rs - GRESOURCE_PREFIX and GLYPH_PREFIX constants

Custom code generation is available via FontBuild::run_with().

Emoji Families: Multi-Crate Layout

crates.io rejects package uploads larger than 10 MiB. The emoji families ship several large TTFs plus thousands of pre-rendered color SVGs, so each family is split into a crate topology instead of a single crate:

fonts-rs-noto-emoji-glyphs       # links resource: single-codepoint SVGs
fonts-rs-noto-emoji-sequences    # links resource: multi-codepoint SVGs (ZWJ, flags, modifiers)
fonts-rs-emoji-metadata          # links resource: shared CLDR/UTS-#51 metadata
fonts-rs-noto-emoji-generator    # shared build pipeline (build-dependency)
fonts-rs-noto-emoji-{mono,color-flags,color-noflags,bitmap-flags,bitmap-noflags}
fonts-rs-noto-emoji              # umbrella: re-exports the feature-selected variant

Blobmoji uses the identical topology with four variants (no mono): fonts-rs-blobmoji-{color-flags,color-noflags,bitmap-flags,bitmap-noflags}.

  • Resource crates carry the vendored artwork and declare a links key (e.g. links = "noto_emoji_glyphs"); their build.rs prints cargo:svg_dir=..., which dependents read as DEP_NOTO_EMOJI_GLYPHS_SVG_DIR. Cargo propagates DEP_* variables only along [dependencies] edges - resource crates are normal dependencies of the variant crates, not build-dependencies. See Upstream Sourcing.
  • Variant crates each vendor one TTF + license file and run the identical export via the family generator’s build(&BuildInput); the variant is a compile-time constant per crate, so feature-based variant detection (VariantList) is not needed. noflags variants filter flag emoji at export time; RENDERABLE is a pub const per crate.
  • The umbrella crate keeps the family’s name (fonts-rs-noto-emoji, fonts-rs-blobmoji), maps variant features to optional dependencies and re-exports the selected variant 1:1. A compile_error! guards against enabling several variants, since Cargo features are additive.
  • Generators (fonts-rs-{family}-generator) host the shared export pipeline; generic emoji machinery (CLDR parsing, ordering, metadata generation) lives in fonts_rs_generator::emoji.

Consumers keep the usual surface: fonts-rs-noto-emoji = "0.5" gets the default variant; default-features = false + features = ["bitmap-flags"] selects another. See Build Patterns for the build-side details.

GResource Registration

The build.rs script compiles GResource bundles via glib-build-tools:

  1. icons.gresource from resources/icons.gresource.xml - contains all exported SVG glyph files
  2. font.gresource (optional) from resources/font.gresource.xml - contains the font file itself for GResource-based font loading

At runtime, MyFont::install() registers the GResource bundle via gio::resources_register_include!("icons.gresource") and loads the TTF. Registration is lazy and idempotent via GtkFont::ensure_registered() - glyph accessors call it automatically.

fonts-rs-model - Generic Model Types

The fonts-rs-model crate provides font-family-agnostic types shared across all fonts-rs-* crates. These types are the foundation of the modular fonts framework, enabling any font family crate to use the same build pipeline without Nerd Fonts dependencies.

FontFamilyMarker (Marker Trait)

A sealed marker trait that identifies each font family at compile time. Each font family crate defines a zero-sized enum implementing FontFamilyMarker and the private Sealed trait. This prevents external crates from defining their own font family markers.

#![allow(unused)]
fn main() {
pub trait FontFamilyMarker: sealed::Sealed {}
}

Used as the phantom type parameter in GlyphName<F>, so that GlyphName<Doto> and GlyphName<SevenSegment> are distinct types at compile time - preventing mix-ups between font families.

Example

#![allow(unused)]
fn main() {
use fonts_rs_model::FontFamilyMarker;
use fonts_rs_model::sealed;

pub enum Doto {}

impl FontFamilyMarker for Doto {}
impl sealed::Sealed for Doto {}
}

FontFamily (Core Trait)

The runtime glyph API implemented by each font family marker type - typically via impl_font_family! in family.rs:

#![allow(unused)]
fn main() {
pub trait FontFamily: FontFamilyMarker + FontFamilyConfig {
    type Name: AsRef<str> + FromStr;
    const VARIANTS: &'static [FontVariant] = &[];

    fn glyph_name(ch: impl Into<CodePoint>) -> Option<Self::Name>;
    fn codepoint(name: impl AsRef<str>) -> Option<CodePoint>;
    fn all_glyphs() -> impl Iterator<Item = (CodePoint, Self::Name)>;
    fn glyph_count() -> usize { Self::all_glyphs().count() }
}
}

The lookup methods are generic: codepoint accepts &str, String, and the typed Self::Name (GlyphName<F> / IconName) via AsRef<str>; glyph_name accepts char and CodePoint via Into<CodePoint>. all_glyphs yields the typed Self::Name - use name.as_ref() when plain &str access is enough.

The macro also emits inherent forwarders, so callers write Doto::codepoint("doto-a") without importing the trait.

FontFamilyConfig (Trait)

Base configuration for all font families. Provides compile-time constants for GResource prefixes, icon context directories, and codepoint ranges. Used by both FontDefinition (type-safe glyph names) and ExportConfig (runtime variant pipeline).

#![allow(unused)]
fn main() {
pub trait FontFamilyConfig {
    const FONT_FAMILY_NAME: &'static str;
    const FAMILY_DISPLAY_NAME: &'static str;
    const GRESOURCE_PREFIX: &'static str;
    const ICONS_CONTEXT: &'static str = ICONS_CONTEXT_GLYPHS;
    const CODEPOINT_RANGES: &[CodePointRange] = &[BMP_RANGE];
    const ICON_PREFIX: &'static str = "";

    fn icons_dir(output_dir: &Path) -> PathBuf { ... }
    fn prepare_icons_dir(output_dir: &Path) -> std::io::Result<PathBuf> { ... }
    fn icons_resource_prefix() -> String { ... }
    fn is_valid_icon_name(name: &str) -> bool { ... }
}
}

Constants

  • FONT_FAMILY_NAME: Slug for GResource prefix and glyph names (e.g. "doto", "dseg7")
  • FAMILY_DISPLAY_NAME: Human-readable name for build logs (e.g. "Doto", "DSEG7")
  • GRESOURCE_PREFIX: Full GResource prefix (e.g. /io/smearor/fonts/doto)
  • ICONS_CONTEXT: Subdirectory after scalable/ - default "glyphs", override e.g. "emoji" for Noto Emoji
  • CODEPOINT_RANGES: Unicode ranges for reverse cmap probing - default BMP, override e.g. ASCII_PRINTABLE_RANGE for barcode fonts
  • ICON_PREFIX: Icon name prefix for icon fonts (e.g. "nf-" for Nerd Fonts, "tabler-" for Tabler). Empty for non-icon families.

Methods

  • prepare_icons_dir: Removes the scalable/{context}/ directory and recreates it (avoids stale SVGs from previous builds)
  • icons_dir: Returns the path to scalable/{context}/ within the output directory
  • icons_resource_prefix: Returns {GRESOURCE_PREFIX}/scalable/{ICONS_CONTEXT} - the canonical resource layout for icon-theme glyphs. Every family ships SVGs at {prefix}/scalable/{context}/{name}.svg; override only when upstream assets demand a different layout.
  • is_valid_icon_name: Validation hook used by IconName<F> - default accepts names starting with ICON_PREFIX; multi-set fonts override it (Nerd Fonts delegates to IconSet prefix detection).

FontDefinition (Trait)

Extends FontFamilyConfig with type-safe glyph name processing and a default export_glyphs pipeline. Used by font families with semantic PostScript glyph names (e.g. Barcode, Seven-Segment).

#![allow(unused)]
fn main() {
pub trait FontDefinition: FontFamilyConfig {
    type Name: AsRef<str> + Clone + Ord + Serialize + for<'a> Deserialize<'a>;
    type Family: FontFamilyMarker;

    fn normalize_name(raw_glyph_name: &str) -> Option<Self::Name>;
    fn should_skip(raw_glyph_name: &str) -> bool { ... }
    fn generate_gresource_xml(...) -> std::io::Result<()> { ... }
    fn export_glyphs(font_path: &Path, output_dir: &Path) -> std::io::Result<usize> { ... }
}
}

Associated Types

  • Name: Glyph name type - GlyphName<Self::Family> for simple families, IconName for Nerd Fonts
  • Family: Font family marker (e.g. Doto, SevenSegment)

Methods

  • normalize_name: Raw glyph name → normalized name (e.g. "zero" → "dseg7-0")
  • should_skip: Filter for glyph names to skip (default: ., uni, u - overridable)
  • export_glyphs: Default pipeline: SVG export, metadata.json, icons.gresource.xml

FontVariant

Identifies a font variant (e.g. "classic-regular", "bold-dot") and describes how it is realized: separate file, variable font axes, or both.

#![allow(unused)]
fn main() {
pub struct FontVariant {
    name: &'static str,
    variant_type: FontVariantType,
}
}

Constructors

#![allow(unused)]
fn main() {
// Separate file, no axes
FontVariant::file("classic-regular", "DSEG7Classic-Regular");

// Shared file, axes only (variable font)
FontVariant::axes("bold-dot", &[AxisValue::new("wght", 700.0), AxisValue::new("ROND", 100.0)]);

// Separate file with additional axes
FontVariant::file_with_axes("bold-extended", "MyFont-Bold", &[AxisValue::new("wdth", 125.0)]);
}

Methods

  • is_active(): Checks the CARGO_FEATURE_{NAME} environment variable
  • slug(): Variant name with _ instead of - (for GResource paths)
  • axis_values(): Returns the axis configuration
  • font_file(): Returns the font file (if separate)

FontVariantType

Describes how a variant is realized:

#![allow(unused)]
fn main() {
pub struct FontVariantType {
    pub font_file: Option<FontFile>,
    pub axis_values: AxisValues,
}
}
  • file(): Separate file, no axes
  • axes(): Shared file, axes only (variable font)
  • file_with_axes(): Separate file with additional axes

Axes (Axis, AxisValue, AxisValues)

Variable font axis identification and values:

#![allow(unused)]
fn main() {
pub struct Axis(&'static str);  // e.g. "wght", "ROND"

pub struct AxisValue {
    pub axis: Axis,
    pub value: f32,
}

pub struct AxisValues(&'static [AxisValue]);
}
  • AxisValues::EMPTY - default location (no axes)
  • AxisValues is const-compatible for VARIANTS arrays in build.rs
  • Deref to [AxisValue] for iteration

CodePointRange

An inclusive Unicode range for reverse cmap probing:

#![allow(unused)]
fn main() {
pub struct CodePointRange {
    start: CodePoint,
    end: CodePoint,
}
}

Predefined constants in fonts-rs-model:

  • BMP_RANGE - U+0000–U+FFFF (Default)
  • ASCII_PRINTABLE_RANGE - U+0020–U+007E
  • PUA_RANGE - U+E000–U+F8FF
  • SUPPLEMENTARY_PUA_RANGE - U+F0001–U+10FFFF

Codepoint Map Types

Newtype wrappers around HashMap for type-safe lookups:

  • CodePointCategoryMap - HashMap<CodePoint, String>: codepoint → category (e.g. from emoji-test.txt)
  • CodePointKeywordMap - HashMap<CodePoint, Vec<String>>: codepoint → keyword list (e.g. from CLDR annotations)
  • CodePointNameMap - HashMap<CodePoint, String>: codepoint → canonical name (e.g. from CLDR tts fields)
  • GlyphNameMap - HashMap<String, CodePoint>: glyph name → codepoint (e.g. from SMuFL glyphnames.json). Implements Deserialize for the SMuFL JSON format { "glyphName": { "codepoint": "U+E050", ... } }.

GlyphEntry<N>

Metadata for a single exported glyph:

#![allow(unused)]
fn main() {
pub struct GlyphEntry<N: AsRef<str>> {
    pub code: Option<CodePoint>,
    pub name: N,
    pub file: PathBuf,
    pub resource_path: ResourcePath,
}
}
  • GlyphEntry::new(code, name, gresource_prefix, icons_context) - constructs file and resource_path automatically from prefix, context, and name
  • Generic over N: GlyphName<F> for type-safe families, String for the ExportConfig pipeline, IconName for Nerd Fonts

GlyphName<F>

Phantom-typed glyph name newtype:

#![allow(unused)]
fn main() {
pub struct GlyphName<F: FontFamilyMarker> {
    name: String,
    _marker: PhantomData<F>,
}
}

Implements AsRef<str>, Display, Serialize, Deserialize, Hash, Eq, Ord. Construction via GlyphName::new(String) after normalization.

Each font family crate defines a type alias:

#![allow(unused)]
fn main() {

}

Glyph Metadata (GlyphMetadata)

Search metadata behind each family’s metadata feature: keywords, categories, and aliases as compile-time phf maps generated by a MetadataGenerator in build.rs (see fonts-rs-generator).

#![allow(unused)]
fn main() {

  • categories() is a filter axis - a glyph may carry several categories; they render as pills in the cheat sheet.

Glyph Ordering (GlyphOrdering)

Optional canonical ordering contract - the generic form of the emoji picker ordering. Consumers obtain Option<&'static dyn GlyphOrdering> via CheatSheetFamily::ordering() and stay family-agnostic:

#![allow(unused)]
fn main() {
pub trait GlyphOrdering: Sync {
    fn order_index(&self, name: &str) -> Option<u32>;     // canonical position, bases only
    fn group(&self, name: &str) -> Option<GroupLabel>;    // label per glyph, variants included
    fn group_labels(&self) -> &'static [GroupLabel];      // jump-list order
    fn groups(&self) -> &'static [GlyphGroup];            // picker layout per group
    fn alternates(&self, name: &str) -> &'static [&'static str] { &[] }
    fn base_of(&self, name: &str) -> Option<&'static str>; // variant -> base
    fn tone_group(&self, name: &str) -> Option<u32> { None }
    fn collapse_variants(&self) -> bool { true }
}
}
  • order_index numbers only base/standalone glyphs; variants sort next to their base via base_of.
  • group/group_labels/groups partition the glyphs (each glyph in exactly one group - unlike categories) and drive the group drop-down plus the sidebar “Groups” section.
  • base_of/alternates link variants (skin tones, styles, upside-down pieces) to their base glyph; the pair powers the detail sidebar’s “Variants”/“Variant of” section.
  • collapse_variants - true lets the browse grid hide variants behind their base (emoji tones, dicefont styles, cuernavaca pieces). Style families (line-awesome, fluent, eva, heroicons) return false: collapsing would hide an entire style from the “All groups” view; the base_of/alternates link still applies for variant links and sorting.
  • tone_group - emoji-only: entries sharing a group have the same alternates shape, so one default-tone choice applies everywhere.

Table sources

Everything is 'static - two proven sources:

  • Codegen’d phf maps (emoji): EmojiOrderingGenerator reads emoji_*_ordering.json in build.rs and emits ORDERING, GROUP_OF, ALTERNATES, BASE_OF, TONE_GROUP, GROUPS.
  • Lazy derivation (no upstream ordering file): a OnceLock-cached OrderingTables struct built once from REVERSE_GLYPHS (all exported names) plus a small static rule table - the line-awesome/nerd-fonts pattern, also used by dicefont and cuernavaca. Group assignment, base_of/alternates links, and the canonical index all derive from name parsing at first use.

Optional capabilities are declared per family in impl_font_family! (capabilities = [...]); each emits an empty impl whose methods are trait defaults built on FontFamily + GtkFont. Valid capability names: icon_theme, pango, html_svg, html.

FontBuild (Builder)

Builder for the common build.rs pipeline. Handles hash-based change detection, conditional glyph export, GResource compilation, and code generator invocation.

#![allow(unused)]
fn main() {
FontBuild::new(&font_path)
    .extra_hash(entry.as_str())     // for variable font variants
    .compile_font_gresource()       // optional: font.gresource
    .rerun_if_changed(path)         // additional cargo:rerun-if-changed
    .additional_gresource(xml, out) // additional GResource bundles
    .run(|font_path, resources_dir| {
        config.export_glyphs(font_path, resources_dir)
    })
    .map_err(|e| miette::miette!("{e}"))?;
}

Builder Methods

  • extra_hash: Additional hash component (e.g. variant name) - forces re-export on variant change even if the font file is unchanged
  • compile_font_gresource: Also compile font.gresource in addition to icons.gresource
  • rerun_if_changed: Add extra cargo:rerun-if-changed paths
  • additional_gresource: Register additional GResource bundles to compile

Run Methods

  • run: Export closure + default code generation (CodemapGenerator + RustConstantsGenerator)
  • run_with: Export closure + custom code generation closure
  • run_svg: Fontless variant - export closure receives only the resources dir (no font path). Must be paired with svg_only()
  • Hash is computed as FNV-1a of the font file and stored in resources/.hash

CodemapGenerator tolerates shared codepoints: when several exported names map to the same codepoint (e.g. Line Awesome regular/solid pairs), the forward char -> name map emits each codepoint exactly once - the canonical (shortest) name wins - while the reverse name -> char map keeps all names. phf_map! rejects duplicate keys, so the dedupe is mandatory, not cosmetic.

Fontless Builds (svg_only)

FontBuild::svg_only() creates a builder without a font file - for icon sets that ship only SVGs (Lucide). Change detection then relies entirely on extra_hash components; callers must hash every input that affects the export:

#![allow(unused)]
fn main() {
FontBuild::svg_only()
    .extra_hash(EXPORT_PIPELINE_VERSION.to_string())
    .extra_hash(format!("{:016x}", hash_svg_dir(&svg_dir)))
    .extra_hash(format!("{:016x}", hash_str(&icons_json)))
    .rerun_if_changed(&svg_dir)
    .run_svg(|resources_dir| {
        SvgDirSource::new(&svg_dir)
            .codepoint_strategy(CodepointStrategy::HashedPua)
            .name_resolver(|parsed| Some(format!("{}-symbolic", parsed.raw_name)))
            .name_prefix(LucideConfig::FONT_FAMILY_NAME)
            .post_process(SymbolicClasses)
            .export(&config, resources_dir)
    })
}
  • EXPORT_PIPELINE_VERSION: a manual constant in build.rs that is mixed into the hash. Bump it whenever the export pipeline itself changes (naming, layout, post-processors) - otherwise a matching hash would reuse a stale export.
  • hash_svg_dir / hash_str: hash helpers for non-font inputs.

GlyphSource (Abstraction)

GlyphSource decouples glyph identity and artwork from the export pipeline. Two implementations feed the shared export runner:

  • FontFileSource - extracts outlines from TTF/OTF via skrifa
  • SvgDirSource - consumes a directory of pre-rendered SVGs

Both emit identical artifacts (metadata.json, icons.gresource.xml, SVG files under scalable/{context}/).

SvgDirSource Builder Methods

  • dir - merge an additional SVG directory into the same export. Used by the emoji families where *-glyphs (single codepoints) and *-sequences (ZWJ/flags/modifiers) are separate resource crates; the sets must be disjoint - the duplicate check is a correctness guard
  • filename_parser - NameParser (default, plain {name}.svg) or EmojiUFilenameParser (emoji_u{cp}.svg)
  • codepoint_strategy - how GlyphDescriptor::code is assigned
  • codepoint_map - name→codepoint map for FromNameMap
  • name_resolver - parsed glyph → semantic name (falls back to the raw filename stem, kebab-normalized; name collisions get a deterministic suffix)
  • name_prefix - prepend {prefix}- to every resolved name
  • filter - drop glyphs by codepoint sequence (e.g. flag emoji)
  • post_process - add an SvgPostProcessor, applied in order

SvgPostProcessor

Trait for transforming each SVG before it is written to the output directory (SvgDirSource::post_process). Implementations should be XML-aware via quick-xml - naive string replacement would also match paint attributes inside comments or metadata.

#![allow(unused)]
fn main() {
pub trait SvgPostProcessor {
    fn process(&self, svg: String) -> Result<String, GlyphSourceError>;
}
}

Available processors:

  • Optimize - whitespace/structure cleanup
  • NormalizeViewBox - normalize the viewBox attribute
  • CurrentColor(target) - rewrite fill/stroke values to currentColor (PaintTarget::Fill/Stroke/Both); keeps none, url(…), inherit. .inject_missing() additionally injects the targeted attribute on <svg> roots that declare none - needed for sets like Line Awesome whose upstream paths carry no paint attribute at all (rewriting alone would be a no-op, leaving implicit black)
  • StripEntityNamespaces - strip internal entity namespace prefixes
  • SymbolicClasses - add GTK symbolic classes for stroke-based icon sets (see below)

SymbolicClasses - Symbolic Recoloring for Stroke-Based Sets

GTK’s symbolic icon recoloring ignores fill/stroke attributes: paints are derived from class tokens (transparent-fill, foreground-fill, foreground-stroke, success-*, warning-*, error-*). Stroke-based sets (Lucide, Tabler outline) authored with fill="none" + stroke="currentColor" therefore render as solid blobs under *-symbolic names: every shape is filled with the foreground color, swallowing the stroked details.

SymbolicClasses maps each shape element’s effective fill/stroke (including values inherited from ancestor <svg>/<g> elements) onto symbolic classes:

Effective paintEmitted class
fill="none"transparent-fill
any other fill / unsetforeground-fill
visible strokeforeground-stroke
stroke="none" / unset(no stroke class → not stroked)

Original attributes are kept, so non-symbolic consumers (HTML export, glyph_svg, compose_svg) are unaffected. Stroke classes require GTK ≥ 4.20 (or GTK 3 ≥ 3.24.50); on older versions stroke-based symbolic icons fall back to fill-only rendering.

build.rs Patterns

There are two main patterns for build.rs, depending on whether the font has variants.

Pattern 1: Variable Font with Variants (e.g. Doto)

Used for variable fonts where the same TTF file is rendered at different axis locations, or for font families with multiple separate font files. Variants are selected via Cargo features at build time.

use std::path::Path;

use fonts_rs_generator::ExportConfig;
use fonts_rs_generator::FontBuild;
use fonts_rs_generator::VariantList;
use fonts_rs_generator::build_constants;
use fonts_rs_generator::set_font_path_env;
use fonts_rs_model::AxisValue;
use fonts_rs_model::FontVariant;

#[path = "src/definition.rs"]
mod definition;
use definition::DotoConfig;

const FONT_FILE: &str = "Doto.ttf";

const VARIANTS: VariantList<DotoConfig> = VariantList::new(&[
    FontVariant::axes("regular-medium", &[AxisValue::new("wght", 500.0), AxisValue::new("ROND", 50.0)]),
    FontVariant::axes("bold-dot", &[AxisValue::new("wght", 700.0), AxisValue::new("ROND", 100.0)]),
    // ...
]);

fn main() -> miette::Result<()> {
    let entry = VARIANTS.detect_and_get_active_variant(12)?;
    let font_path = Path::new(build_constants::RESOURCES_DIR).join(FONT_FILE);

    eprintln!("build.rs: active variant: {} -> {}", entry, font_path.display());

    set_font_path_env("DOTO_FONT_PATH", &font_path)?;

    let config = ExportConfig::<DotoConfig>::with_variant(*entry);

    FontBuild::new(&font_path)
        .extra_hash(entry.as_str())
        .run(|font_path, resources_dir| config.export_glyphs(font_path, resources_dir))
        .map_err(|e| miette::miette!("{e}"))?;

    config.write_variant_info()?;
    Ok(())
}

Key points:

  • VariantList::new(&[...]) defines all variants as a const array
  • detect_and_get_active_variant(default_index) scans Cargo features
  • extra_hash(entry.as_str()) forces re-export when the variant changes
  • ExportConfig::with_variant(*entry) creates variant-specific config
  • write_variant_info() generates OUT_DIR/variant.rs

Pattern 2: Static Font with External Name Map (e.g. Bravura)

Used for fonts without PostScript glyph names (e.g. SMuFL fonts with post table version 3.0). Glyph names come from an external metadata file (e.g. glyphnames.json).

use std::path::Path;

use fonts_rs_generator::ExportConfig;
use fonts_rs_generator::FontBuild;
use fonts_rs_generator::build_constants;
use fonts_rs_generator::set_font_path_env;
use fonts_rs_model::GlyphNameMap;

#[path = "src/definition.rs"]
mod definition;
use definition::BravuraConfig;

const FONT_FILE: &str = "Bravura.otf";
const GLYPHNAMES_FILE: &str = "glyphnames.json";

fn parse_glyphnames(json: &str) -> miette::Result<GlyphNameMap> {
    serde_json::from_str(json).map_err(|e| miette::miette!("Failed to parse glyphnames.json: {e}"))
}

fn main() -> miette::Result<()> {
    let font_path = Path::new(build_constants::RESOURCES_DIR).join(FONT_FILE);
    let glyphnames_path = Path::new(build_constants::RESOURCES_DIR).join(GLYPHNAMES_FILE);

    eprintln!("build.rs: exporting glyphs from {}", font_path.display());

    set_font_path_env("BRAVURA_FONT_PATH", &font_path)?;

    let glyphnames_json = std::fs::read_to_string(&glyphnames_path)
        .map_err(|e| miette::miette!("Failed to read {}: {e}", glyphnames_path.display()))?;
    let name_map = parse_glyphnames(&glyphnames_json)?;
    eprintln!("build.rs: parsed {} SMuFL glyph names", name_map.len());

    let config = ExportConfig::<BravuraConfig>::new();

    FontBuild::new(&font_path)
        .run(|font_path, resources_dir| {
            config.export_glyphs_by_name_map(font_path, resources_dir, &name_map)
        })
        .map_err(|e| miette::miette!("{e}"))?;

    config.write_variant_info()?;
    Ok(())
}

Key points:

  • ExportConfig::new() - no variant, uses family config defaults
  • export_glyphs_by_name_map() - uses external name→codepoint mapping
  • No extra_hash needed (no variant selection)

Pattern 3: Multi-Crate Emoji Family

Used when the vendored resources are too large for a single crate - crates.io rejects .crate uploads over 10 MiB, and the emoji families carry several TTFs plus thousands of pre-rendered SVGs. The family is split into four crate kinds:

  • Resource crates (*-glyphs, *-sequences) hold the vendored SVG artwork, partitioned by the emoji_u* filename grammar. They declare a unique links key and emit their directory via build.rs:

    #![allow(unused)]
fn main() {
// fonts-rs-blobmoji-glyphs/build.rs
println!("cargo:svg_dir={}", manifest_dir.join("resources/svg").display());
println!("cargo::rerun-if-changed=resources");
}

    Dependents read it as DEP_<LINKS>_SVG_DIR. Important: DEP_* variables propagate only along [dependencies] edges - resource crates must be normal dependencies of the variant crate, never [build-dependencies].

  • A generator crate (fonts-rs-{family}-generator) hosts the shared export pipeline as build(&BuildInput), so every variant produces byte-identical output modulo the variant parameters. BuildInput carries svg_dirs (one per resource crate), a metadata_dir (fonts-rs-emoji-metadata, shared between the emoji families), the Variant and the *_FONT_PATH env var name.

  • Variant crates (fonts-rs-{family}-{variant}) vendor exactly one TTF + the license file. There is no VariantList feature detection - the variant is a compile-time constant:

    // fonts-rs-blobmoji-color-flags/build.rs
fn main() -> miette::Result<()> {
    build(&BuildInput {
        svg_dirs: vec![dep_dir("DEP_BLOBMOJI_GLYPHS_SVG_DIR")?, dep_dir("DEP_BLOBMOJI_SEQUENCES_SVG_DIR")?],
        metadata_dir: dep_dir("DEP_EMOJI_METADATA_DIR")?,
        variant: Variant::ColorFlags,
        font_path_env: "BLOBMOJI_FONT_PATH",
    })
}

    Inside the generator’s build, the svg_dirs are merged into one SvgDirSource via .dir(...) - the directories partition the glyph set, so the duplicate check is a correctness guard. noflags variants pass include_flags = false, filtering flag emoji at export time. pub const RENDERABLE per crate replaces the old compile-time *_bitmap cfgs.

  • The umbrella crate keeps the family name and maps variant features to optional dependencies:

    [features]
default = ["gtk", "color-flags"]
color-flags = ["dep:fonts-rs-blobmoji-color-flags"]
bitmap-flags = ["dep:fonts-rs-blobmoji-bitmap-flags"]
# forwarded to whichever variant is active (weak deps)
gtk = ["fonts-rs-blobmoji-color-flags?/gtk", "fonts-rs-blobmoji-bitmap-flags?/gtk"]

    lib.rs re-exports the selected variant and guards against multi-variant selection with compile_error! (features are additive). Consumers get fonts-rs-blobmoji = "0.5" or pick a variant via default-features = false, features = ["bitmap-flags"]; the variant crates can also be used directly for smaller dependency trees.

See crates/fonts-rs-noto-emoji-generator/src/build/pipeline.rs and crates/fonts-rs-blobmoji-generator/src/build/pipeline.rs for the shared pipelines.

lib.rs + family.rs - Runtime API

Each font family crate wires the generated phf maps into the FontFamily trait via impl_font_family! in family.rs:

#![allow(unused)]
fn main() {
// family.rs
use crate::codepoint_map;
use crate::definition::DotoConfig;
use crate::naming::Doto;
use crate::naming::DotoName;
use crate::variant;

The macro emits the FontFamily impl (codepoint, glyph_name, all_glyphs, glyph_count), the declared capability impls, and inherent forwarders so callers write Doto::codepoint("x") without importing the trait.

Valid capability names: icon_theme (IconThemeFont - GtkIconTheme registration + glyph_svg/compose_svg), pango (PangoFont), html_svg (HtmlSvgExport - inline-SVG HTML export), html (HtmlExport - @font-face HTML export on top of html_svg). Fontless icon sets declare only [icon_theme, html_svg] - there is no TTF for pango or font-face export. SoftwareRender is not a capability here; it is emitted by impl_font_loader!.

Adding a New Font Family

This guide walks through creating a new font family crate in the fonts-rs workspace. The process is designed to require minimal boilerplate - most of the build pipeline is handled by the generic framework in fonts-rs-generator.

Overview

A font family crate integrates a TTF/OTF font into the fonts-rs ecosystem, providing:

  • Build-time glyph export to SVG files
  • GResource bundle compilation for GTK
  • Codepoint map generation (phf::Map)
  • Runtime glyph name resolution and GResource registration
  • Optional software rendering via ab_glyph

Step 1: Create the Crate

Create a new directory under crates/:

crates/fonts-rs-{name}/
├── Cargo.toml
├── build.rs
├── resources/
│   └── {font}.ttf
└── src/
    ├── lib.rs
    ├── definition.rs
    ├── naming.rs
    ├── variant.rs
    ├── codepoint_map.rs
    ├── constants.rs
    └── fonts.rs       (optional)

Step 2: Vendor the Upstream Assets

Everything under resources/ that comes from an upstream project is vendored, not copied by hand: write upstream.toml first, then let cargo xtask sync -p fonts-rs-{name} materialize it. The manifest declares where each file comes from (a pinned git ref or an immutable URL); sync produces resources/ plus upstream.lock, and both are committed:

# crates/fonts-rs-{name}/upstream.toml
[upstream]
repo = "myproject/myfont"     # owner/name shorthand or git URL
ref = "v1.2.3"                # tag, branch or commit SHA

[upstream.license]
source = "OFL.txt"
target = "resources/OFL.txt"

[[artifacts]]
url = "https://github.com/myproject/myfont/releases/download/v1.2.3/MyFont-Regular.ttf"
target = "resources/MyFont-Regular.ttf"

cargo xtask sync -p fonts-rs-{name}    # writes resources/ + upstream.lock
cargo xtask verify -p fonts-rs-{name}  # sanity check

Result:

resources/
├── MyFont-Regular.ttf
└── OFL.txt            (or appropriate license)

Curated files without an upstream source may live in resources/ too - verify warns about them (no lock entry) but accepts them. See the Upstream Sourcing chapter for the full upstream.toml schema, provider-generated metadata ([[metadata]]) and the update-bump procedure (sync --update).

Step 3: Write definition.rs

Implement FontFamilyConfig with the family’s constants:

#![allow(unused)]
fn main() {
//! `FontFamilyConfig` for the MyFont font family.

use const_format::concatcp;
use fonts_rs_generator::FontFamilyConfig;
use fonts_rs_model::CodePointRange;
use fonts_rs_model::GRESOURCE_BASE_PREFIX;
use fonts_rs_model::PUA_RANGE;

pub struct MyFontConfig;

impl FontFamilyConfig for MyFontConfig {
    const FONT_FAMILY_NAME: &'static str = "myfont";
    const FAMILY_DISPLAY_NAME: &'static str = "MyFont";
    const GRESOURCE_PREFIX: &'static str = concatcp!(GRESOURCE_BASE_PREFIX, "/", MyFontConfig::FONT_FAMILY_NAME);
    const CODEPOINT_RANGES: &[CodePointRange] = &[PUA_RANGE];
}
}

Choose CODEPOINT_RANGES based on the font’s Unicode coverage:

  • BMP_RANGE - full BMP (default, most fonts)
  • ASCII_PRINTABLE_RANGE - barcode fonts, seven-segment display fonts
  • PUA_RANGE - SMuFL music fonts, icon fonts in the Private Use Area

Step 4: Write naming.rs

Define the FontFamilyMarker enum and GlyphName<F> type alias:

#![allow(unused)]

use fonts_rs_model::GlyphName;
use fonts_rs_model::sealed;

impl sealed::Sealed for MyFont {}

Step 5: Write build.rs

Choose the pattern that matches your font:

Variable Font with Variants

If the font has multiple variants (e.g. weight/roundness combinations), use VariantList + ExportConfig::with_variant:

use std::path::Path;

use fonts_rs_generator::ExportConfig;
use fonts_rs_generator::FontBuild;
use fonts_rs_generator::VariantList;
use fonts_rs_generator::build_constants;
use fonts_rs_generator::set_font_path_env;
use fonts_rs_model::AxisValue;
use fonts_rs_model::FontVariant;

#[path = "src/definition.rs"]
mod definition;
use definition::MyFontConfig;

const FONT_FILE: &str = "MyFont.ttf";

const VARIANTS: VariantList<MyFontConfig> = VariantList::new(&[
    FontVariant::axes("regular", &[AxisValue::new("wght", 400.0)]),
    FontVariant::axes("bold", &[AxisValue::new("wght", 700.0)]),
]);

fn main() -> miette::Result<()> {
    let entry = VARIANTS.detect_and_get_active_variant(0)?;
    let font_path = Path::new(build_constants::RESOURCES_DIR).join(FONT_FILE);

    set_font_path_env("MYFONT_FONT_PATH", &font_path)?;

    let config = ExportConfig::<MyFontConfig>::with_variant(*entry);

    FontBuild::new(&font_path)
        .extra_hash(entry.as_str())
        .run(|font_path, resources_dir| config.export_glyphs(font_path, resources_dir))
        .map_err(|e| miette::miette!("{e}"))?;

    config.write_variant_info()?;
    Ok(())
}

Pre-rendered SVGs (Hybrid)

If the upstream project ships full-color source SVGs (e.g. Blobmoji, Tabler Icons), use SvgDirSource for the GResource and bundle the TTF separately for pixel-drawing. Glyph names come from an external name map or a name_resolver closure; codepoints come from the filename or a GlyphNameMap:

#![allow(unused)]
fn main() {
use fonts_rs_generator::CodepointStrategy;
use fonts_rs_generator::ExportConfig;
use fonts_rs_generator::FontBuild;
use fonts_rs_generator::GlyphSource;
use fonts_rs_generator::SvgDirSource;
use fonts_rs_generator::build_constants;

let config = ExportConfig::<MyFontConfig>::with_variant(*entry);
let svg_dir = Path::new(build_constants::RESOURCES_DIR).join("svg");

FontBuild::new(&font_path)
    .compile_font_gresource()
    .gresource_prefix(MyFontConfig::GRESOURCE_PREFIX)
    .extra_hash(format!("{}-{:016x}", entry.as_str(), hash_svg_dir(&svg_dir)))
    .run(|_font_path, resources_dir| {
        SvgDirSource::new(&svg_dir)
            .filename_parser(EmojiUFilenameParser)       // or default NameParser
            .codepoint_strategy(CodepointStrategy::FromFilename) // or FromNameMap
            .name_resolver(move |parsed| /* map to semantic name */ { todo!() })
            .name_prefix(&glyph_name_prefix)
            .filter(move |codepoints| /* e.g. drop flags for *-noflags */ true)
            .export(&config, resources_dir)
    })
    .map_err(|e| miette::miette!("{e}"))?;
}

Key points:

  • SvgDirSource iterates resources/svg/ - no TTF outline extraction. The SVGs are the final artwork (full color).
  • filename_parser maps filenames to codepoints (EmojiUFilenameParser for emoji_u{cp}.svg, NameParser for plain {name}.svg like Tabler).
  • codepoint_strategy assigns codepoints: FromFilename (emoji codepoints in the filename) or FromNameMap (external GlyphNameMap, e.g. Tabler’s icons.json unicode values).
  • name_resolver maps parsed filenames to semantic names (e.g. CLDR tts names for emoji, format!("{name}-symbolic") for icons).
  • filter drops glyphs per variant (e.g. flag emoji for *-noflags).
  • dir(other) merges a second SVG directory into the same source - used when the artwork is split across links resource crates (*-glyphs + *-sequences for the emoji families). The sets must partition the glyph space; duplicates are a hard error.
  • extra_hash must cover the SVG directory - the default hash only covers the TTF file, so SVG changes would not trigger a re-export. Call it once per input directory (hash_svg_dir).

When the vendored artwork plus TTFs would exceed the crates.io 10 MiB package limit, the family is split into resource crates, one crate per TTF variant, a generator crate and an umbrella - see Build Patterns (the emoji families use exactly that topology).

See crates/fonts-rs-blobmoji-generator/src/build/pipeline.rs and crates/fonts-rs-noto-emoji-generator/src/build/pipeline.rs (CLDR name map + flag filter) and crates/fonts-rs-tabler/build.rs (FromNameMap + metadata) for complete implementations.

Fontless SVG-Only Icon Set

Icon sets that ship only SVGs - no TTF at all (e.g. Lucide) - use FontBuild::svg_only() + run_svg(). There is no font file to hash, so change detection relies entirely on extra_hash components: hash the SVG directory, metadata files, and a manual EXPORT_PIPELINE_VERSION constant (bump it when the export pipeline itself changes - naming, post-processors):

#![allow(unused)]
fn main() {
const EXPORT_PIPELINE_VERSION: u32 = 1;

FontBuild::svg_only()
    .extra_hash(EXPORT_PIPELINE_VERSION.to_string())
    .extra_hash(format!("{:016x}", hash_svg_dir(&svg_dir)))
    .extra_hash(format!("{:016x}", hash_str(&icons_json)))
    .rerun_if_changed(&svg_dir)
    .run_svg(|resources_dir| {
        SvgDirSource::new(&svg_dir)
            .codepoint_strategy(CodepointStrategy::HashedPua)
            .name_resolver(|parsed| Some(format!("{}-symbolic", parsed.raw_name)))
            .name_prefix(MyFontConfig::FONT_FAMILY_NAME)
            .post_process(SymbolicClasses)   // stroke-based sets: symbolic classes
            .export(&config, resources_dir)
    })
    .map_err(|e| miette::miette!("{e}"))?;
}

Key points:

  • CodepointStrategy::HashedPua allocates a stable PUA codepoint per glyph via hash-of-name - needed because the phf maps require unique codepoints and upstream ships none.
  • post_process(SymbolicClasses) adds GTK symbolic classes to stroke-based SVGs. Without it, *-symbolic icons render as solid blobs - GTK’s symbolic recoloring ignores fill="none" and fills every shape. Requires GTK ≥ 4.20 for stroke rendering.
  • No set_font_path_env, no font.gresource, no render/pango capability - lib.rs declares only [icon_theme, html_svg].

See crates/fonts-rs-lucide/build.rs for the complete implementation.

Multi-TTF Webfont Family (One TTF per Style)

Icon sets that ship one TTF per style (Font Awesome 5 model - e.g. Line Awesome with la-regular-400/la-solid-900/la-brands-400) are a hybrid: GResource SVGs from a vendored svg/ directory plus a font.gresource bundling all faces:

#![allow(unused)]
fn main() {
let font_path = resources.join("fonts").join("la-solid-900.ttf");

// Per-face paths for ab_glyph/pixel-drawing at runtime:
set_font_path_env("MYFONT_REGULAR_FONT_PATH", &resources.join("fonts").join("my-regular.ttf"))?;
set_font_path_env("MYFONT_SOLID_FONT_PATH", &font_path)?;

FontBuild::new(&font_path)
    .compile_font_gresource()   // NO .gresource_prefix() - see below
    .extra_hash(format!("{EXPORT_PIPELINE_VERSION}"))
    .extra_hash(format!("{:016x}", hash_svg_dir(&svg_dir)))
    .extra_hash(format!("{:016x}", hash_str(&codepoints_json)))
    .rerun_if_changed(&svg_dir)
    .rerun_if_changed(resources.join("fonts"))
    .run(|_font_path, resources_dir| {
        SvgDirSource::new(&svg_dir)
            .codepoint_map(&codepoints)
            .codepoint_strategy(CodepointStrategy::FromNameMap)
            .post_process(CurrentColor::new(PaintTarget::Fill).inject_missing())
            .export(&config, resources_dir)
    })?;
}

Key differences from a single-TTF family:

  • Static resources/font.gresource.xml - when compile_font_gresource() is called without gresource_prefix(...), FontBuild falls back to the hand-written manifest in resources/ instead of generating one. The generated manifest covers exactly one TTF; a static manifest can list all faces with aliases.
  • Manual GtkFont impl - impl_gtk_font! cannot express multi-TTF families. Implement it by hand with your own FONT_RESOURCE_PATH constant(s) for the bundled faces; the load_font_from_gresource(path, tag) helper still collapses the OnceLock + temp-extraction body to one call.
  • Manual PangoFont::install_pango - a three-line override that calls the shared PangoFont::install_pango_resources(font_map, &RESOURCE_PATHS, crate_name) helper once per face.
  • CurrentColor::inject_missing() - required when upstream SVG paths carry no paint attribute at all (plain CurrentColor rewriting would be a no-op); it injects fill="currentColor" on the <svg> root. Add a post-export assertion that every emitted SVG actually contains the injected fill.
  • Shared codepoints - style pairs (e.g. adjust / adjust-solid) share one FA5 codepoint. CodemapGenerator dedupes the forward char -> name map per codepoint (the canonical/shortest name wins) while the reverse name -> char map keeps every exported name - phf_map! rejects duplicate keys.
  • SoftwareRender needs a variant enum (LineAwesomeStyle) to select the face, since type Variant = () cannot express multiple TTFs.

See crates/fonts-rs-line-awesome/build.rs and src/gtk.rs for the complete implementation.

Upstream Sourcing

Every crate that vendors files from an upstream project declares its sources in upstream.toml and records the resolved result in upstream.lock, both committed next to resources/. The xtask helper crate provides three commands to work with them:

cargo xtask sync -p <crate>     # populate/refresh resources/
cargo xtask check [-p <crate>]  # report upstream drift
cargo xtask verify [-p <crate>] # re-hash committed resources

Vendored artifacts stay in git. Builds never touch the network - xtask writes resources/; reproducibility means “re-derivable on demand”, not “fetched at build time”.

upstream.toml

The sourcing manifest of a vendored crate. It has three sections; all paths are relative and must not escape the crate/checkout (.. and absolute paths are rejected). Targets must be unique across license, artifacts and metadata.

[upstream] - git source (optional)

Crates sourced purely from url artifacts omit this section entirely.

[upstream]
repo = "tailwindlabs/heroicons"        # owner/name shorthand or full git URL
ref = "v2.2.0"                         # tag, branch or commit SHA

[upstream.license]                     # optional
source = "LICENSE"                     # path inside the upstream checkout
target = "resources/LICENSE"           # vendored path below the crate dir

sparse = [                             # optional, extra checkout paths
  "icons/*.json",                      # for provider inputs not covered
  "categories/*.json",                 # by artifact/license sources
]

The checkout itself is sparse and content-cached: xtask resolves the ref via git ls-remote, then fetches with --depth 1 --filter=blob:none into ~/.cache/fonts-rs/upstream/<repo>/<commit> with a --no-cone sparse checkout covering only the paths the manifest needs. The first path component of every source (artifacts and license) is included automatically; add sparse only for extra inputs providers read from the checkout (e.g. per-icon JSON metadata).

[[artifacts]] - file copies

# Directory copy, glob-filtered:
[[artifacts]]
source = "optimized/24/outline"        # dir or file inside the checkout
target = "resources/svg/outline"       # dir for globs, file for 1:1 copies
pattern = "*.svg"                      # optional, default "**/*"
exclude = ["hidden-icon.svg"]          # optional curated exclusions

# URL fetch (no checkout needed; mutually exclusive with `source`):
[[artifacts]]
url = "https://raw.githubusercontent.com/google/fonts/bd8f81d/.../OFL.txt"
target = "resources/LICENSE.txt"
  • source - a file inside the upstream checkout for 1:1 copies, or a directory scanned recursively against pattern. Mutually exclusive with url.
  • url - an external URL fetched verbatim at sync time (release assets, pinned raw-file URLs, API endpoints). pattern/exclude do not apply. Pin immutable URLs: release assets, commit-SHA paths, versioned CDN URLs - anything mutable will fail verify silently later.
  • pattern - glob relative to source (e.g. **/*.svg). Matched files are flattened into target by basename.
  • exclude - globs skipped even when pattern matches (curated exclusions, e.g. icons intentionally not in the set).

[[metadata]] - provider-generated files

[[metadata]]
provider = "iconify_aliases"
output = "resources/metadata/aliases.json"
with.iconify_set = "heroicons"
with.suffixes = ["-16-solid", "-20-solid", "-solid"]

A provider generates file content from the upstream checkout and/or fetched external inputs, driven by its with.* parameters. Registered providers:

Providerwith.* parametersGenerates
copysourceverbatim copy of one checkout file
eva_metadatasourcename/tag metadata from an upstream file
heroicons_keywordssite (optional, default https://heroicons.com)search keywords extracted from the site JS bundle
iconify_aliasesiconify_set, suffixes, version (optional)v1→v2 style alias map from iconify’s icons.json
line_awesome_aliases-FA4/FA5 compatibility aliases from LA stylesheets
line_awesome_codepoints-$la-{name}: \fXXX codepoint map from _variables.scss
lucide_metadatasource, fieldsmerged per-icon metadata from a JSON directory

upstream.lock

Generated by sync - never edited by hand. Records the resolved upstream coordinates plus the SHA-256 of every vendored file:

[upstream]
repo = "tailwindlabs/heroicons"
ref = "v2.2.0"
commit = "616b7a4dbbf3d011760af8066262cd5c6b3868f3"

[[artifacts]]
target = "resources/svg/outline/academic-cap.svg"
sha256 = "…"
source = "optimized/24/outline/academic-cap.svg"

[[inputs]]
url = "https://unpkg.com/@iconify-json/heroicons@1/icons.json"
sha256 = "…"
provider = "iconify_aliases"
  • [upstream] - absent for URL-only manifests. commit is the resolved SHA; ref is the manifest pin that produced it.
  • [[artifacts]] - every vendored file: target (crate-relative), sha256 (content), source (checkout path or provider:<name>).
  • [[inputs]] - external non-git inputs fetched by providers (url + sha256 + provider), recorded for provenance.

Resource crates

Vendored payloads can live in dedicated resource crates so several crates share them (or so a large payload is split under the crates.io 10 MiB limit - the emoji families do exactly this). A resource crate declares a unique links key and emits directory paths from its build.rs:

# fonts-rs-blobmoji-glyphs/Cargo.toml
links = "blobmoji_glyphs"

#![allow(unused)]
fn main() {
// fonts-rs-blobmoji-glyphs/build.rs
println!("cargo:svg_dir={}", manifest_dir.join("resources/svg").display());
println!("cargo::rerun-if-changed=resources");
}

Cargo exposes each cargo:<key>=<value> line to dependents’ build.rs as DEP_<LINKS>_<KEY> (DEP_BLOBMOJI_GLYPHS_SVG_DIR here). Two rules matter:

  • DEP_* only flows along [dependencies] edges. Resource crates must be declared as normal dependencies of the crate whose build.rs consumes the variable - declaring them under [build-dependencies] yields an unset variable.
  • A links crate still needs a lib target - a stub src/lib.rs suffices; the crate carries no runtime API.

Resource crates vendored from upstream carry their own upstream.toml/upstream.lock with disjoint pattern/exclude slices of the upstream tree - e.g. fonts-rs-blobmoji-glyphs pins emoji_u*.svg minus emoji_u*_*, fonts-rs-blobmoji-sequences pins emoji_u*_*. verify and check cover them like any other vendored crate, so the byte-exact guarantee is unchanged.

Commands

cargo xtask sync -p <crate> [--update]

Resolves the manifest pin (or, with --update, the newest version-like tag / remote HEAD), materializes the sparse checkout, copies [[artifacts]], runs [[metadata]] providers, then writes upstream.lock. Re-running sync on an unchanged manifest refreshes resources/ from the same lock coordinates - byte-identical unless a provider’s external input drifted.

cargo xtask check [-p <crate>] [--json]

Reports drift without touching resources/: for each crate whether the pinned ref moved upstream (new tag, HEAD advanced), whether provider inputs changed (bundle re-fetched and re-hashed), and any fetch errors. --json emits a machine-readable report. Without -p, checks every vendored crate and prints an aggregate report. A weekly scheduled CI job runs this check.

cargo xtask verify [-p <crate>]

SHA-256s every locked file against committed resources/ and reports missing/mismatch by name - non-zero exit on any failure. Files in resources/ without a lock entry produce a warning (unknown hand-adds) but do not fail. This runs as a gate on every pull request: committed resources can never silently diverge from the lock.

Bump procedure

Bumping a crate to a newer upstream is a normal review flow:

cargo xtask sync -p fonts-rs-heroicons --update   # re-pin manifest + re-vendor
git diff crates/fonts-rs-heroicons                # review resources/ + manifest + lock
cargo xtask verify -p fonts-rs-heroicons          # sanity check
cargo build -p fonts-rs-heroicons                 # rebuild generated code

--update picks the newest version-like tag when upstream releases; otherwise it follows the remote default HEAD. Review the diff - a bump is “commit resources/ + upstream.toml + upstream.lock”, all in one reviewable change.

Writing a provider

A provider is a unit-testable Rust type implementing the Provider trait in xtask/src/providers/:

#![allow(unused)]
fn main() {
use crate::providers::Provider;
use crate::providers::ProviderContext;
use crate::providers::ProviderOutput;
use crate::providers::required_string;

/// `my_provider`: reads `with.source` from the checkout and emits JSON.
pub struct MyProvider;

impl Provider for MyProvider {
    fn name(&self) -> &'static str {
        "my_provider"
    }

    fn generate(&self, context: &ProviderContext) -> miette::Result<ProviderOutput> {
        let source = required_string(context.with, "source", self.name())?;
        let text = std::fs::read_to_string(context.checkout()?.join(source))?;
        let content = transform(text)?;
        Ok(ProviderOutput::file(content.into_bytes()))
    }
}
}
  • ProviderContext.checkout - Option<&Path>: root of the upstream sparse checkout, None for URL-only manifests. Call context.checkout()? to require it, or source purely via http_get.
  • ProviderContext.with - the [[metadata]] with.* parameter table (toml::Table). Use required_string / required_string_list for mandatory keys.
  • ProviderContext.http_get(url) - shared per-sync HTTP fetch cache: one request per URL regardless of how many providers need it.
  • ProviderOutput.content - the generated file written to output.
  • ProviderOutput.inputs - every external URL fetched while generating (recorded as [[inputs]] in the lock). Use ProviderOutput::file(content) when there are none.

Register the provider by name in resolve_provider in xtask/src/providers/mod.rs, and extend the registry test - the manifest fails with “Unknown metadata provider” otherwise. Keep the generated output deterministic (sorted maps, stable formatting) so verify and check see real drift rather than serialization noise.

Glyph Resolution

Each font family crate provides glyph name resolution - mapping human-readable glyph names to Unicode codepoints and vice versa.

Font Family Crates

Each font family marker type implements the FontFamily trait, which provides glyph name resolution as associated functions - no trait import needed thanks to inherent forwarders:

#![allow(unused)]
fn main() {
use fonts_rs_doto::Doto;

// Look up a glyph by name
if let Some(codepoint) = Doto::codepoint("doto-a") {
    println!("Glyph codepoint: U+{:04X}", codepoint.as_char() as u32);
}

// Reverse lookup: codepoint → glyph name

    println!("Glyph name: {name}");
}
}

codepoint() looks up the glyph name in the generated phf::Map (REVERSE_GLYPHS), trying both the bare name and the prefixed name ({GLYPH_PREFIX}-{name}).

Nerd Fonts (nerd-fonts-rs)

Nerd Fonts use a different naming convention. Icon names follow the pattern nf-{prefix}-{name}, for example:

  • nf-fa-gamepad - Font Awesome gamepad icon
  • nf-md-cube - Material Design cube icon
  • nf-linux-tux - Linux Tux icon

NerdFonts::codepoint accepts all IconName forms - it normalizes the input to kebab-case, lower-case, strips the nf- prefix and -symbolic suffix, then looks up the name in the vendored codepoint map.

Usage

#![allow(unused)]
fn main() {
use nerd_fonts_rs::CodePoint;
use nerd_fonts_rs::NerdFonts;

// Basic resolution
let codepoint = NerdFonts::codepoint("nf-fa-gamepad");
assert_eq!(codepoint, Some(CodePoint::from_char('\u{F11B}')));

// Underscores are normalized to hyphens
let codepoint = NerdFonts::codepoint("nf_linux_tux");
assert_eq!(codepoint, Some(CodePoint::from_char('\u{F31A}')));

// Case-insensitive
let codepoint = NerdFonts::codepoint("NF-FA-GAMEPAD");
assert_eq!(codepoint, Some(CodePoint::from_char('\u{F11B}')));

// Already has -symbolic suffix
let codepoint = NerdFonts::codepoint("nf-fa-gamepad-symbolic");
assert_eq!(codepoint, Some(CodePoint::from_char('\u{F11B}')));

// Unknown icon returns None
let codepoint = NerdFonts::codepoint("nf-nonexistent-icon-xyz");
assert_eq!(codepoint, None);
}

Glyph Export

Glyphs become GTK4 symbolic SVG icons at build time. The export logic lives in the fonts-rs-generator crate behind the GlyphSource abstraction - FontFileSource extracts outlines from TTF/OTF files via skrifa, SvgDirSource consumes directories of pre-rendered SVGs (emoji sets, icon sets like Tabler and Lucide). Both feed the same export runner and emit identical artifacts. Each family crate’s build.rs invokes the pipeline automatically.

Automatic Generation

build.rs generates the icon resources on demand via FontBuild. The export is triggered when the font file hash has changed since the last export:

flowchart TD
    A["build.rs runs"] --> B{"resources/.hash exists?"}
    B -->|No| D["Export glyphs from font"]
    B -->|Yes| C{"Font hash matches?"}
    C -->|No| D
    C -->|Yes| E["Skip export"]
    D --> F["Write SVGs, metadata.json, icons.gresource.xml"]
    F --> G["Write .hash"]
    E --> H["Compile GResource bundles"]
    G --> H
    H --> I["Generate phf::Map + icon constants"]

resources/{font}.ttf
  ↓  build.rs (skrifa outline extraction, via ExportConfig)
resources/scalable/glyphs/*.svg   (SVG files)
resources/metadata.json           (name, codepoint, file path)
resources/icons.gresource.xml     (GResource manifest)
resources/.hash                   (FNV-1a hash of font file)
  ↓  build.rs (code generation via FontBuild)
$OUT_DIR/codemap.rs               (phf::Map<char, &str> + phf::Map<&str, char>)
$OUT_DIR/icons.rs                 (icon name constants)
$OUT_DIR/variant.rs               (GRESOURCE_PREFIX + GLYPH_PREFIX)
  ↓  build.rs (glib-build-tools)
icons.gresource                   (icon GResource bundle)

The generated files (scalable/, metadata.json, icons.gresource.xml, .hash) are in .gitignore and not checked into the repository. They are regenerated from the font file as needed.

Caching

FontBuild uses two mechanisms for caching:

Cargo rebuild triggers (cargo:rerun-if-changed):

  • The font file - triggers build.rs re-execution
  • resources/metadata.json - triggers phf::Map regeneration
  • resources/icons.gresource.xml - triggers GResource recompilation
  • build.rs - triggers full rebuild

Font hash comparison (FNV-1a): When build.rs runs, it computes an FNV-1a hash of the font file and compares it against the stored hash in resources/.hash. If the hashes differ (or the file is missing), the full glyph export is triggered. Otherwise the export is skipped.

For variable font variants, extra_hash() adds the variant name to the hash, forcing re-export when the active variant changes even if the font file is unchanged.

This means:

  • Fresh clone: hash missing → export runs
  • Font updated: hash differs → export runs automatically
  • No changes: hash matches → export skipped (fast incremental build)
  • Variant changed: extra hash differs → export runs

No manual rm -rf or cargo clean is needed when updating the font file.

Two Export Methods

ExportConfig::export_glyphs (struct method)

Used by most font family crates. Normalizes glyph names to {glyph_name_prefix}-{kebab} and renders SVGs with the configured axis location. Supports name_filter for custom glyph filtering.

#![allow(unused)]
fn main() {
let config = ExportConfig::<DotoConfig>::with_variant(*entry);

FontBuild::new(&font_path)
    .extra_hash(entry.as_str())
    .run(|font_path, resources_dir| config.export_glyphs(font_path, resources_dir))
    .map_err(|e| miette::miette!("{e}"))?;
}

ExportConfig::export_glyphs_by_name_map (struct method)

Used by fonts without PostScript glyph names (e.g. SMuFL fonts with post table version 3.0). Glyph names come from an external metadata file parsed into a GlyphNameMap.

#![allow(unused)]
fn main() {
let name_map: GlyphNameMap = serde_json::from_str(&glyphnames_json)?;
let config = ExportConfig::<BravuraConfig>::new();

FontBuild::new(&font_path)
    .run(|font_path, resources_dir| {
        config.export_glyphs_by_name_map(font_path, resources_dir, &name_map)
    })
    .map_err(|e| miette::miette!("{e}"))?;
}

FontDefinition::export_glyphs (trait default method)

Used by font families with semantic PostScript glyph names (e.g. Barcode, Seven-Segment). Uses Self::normalize_name for type-safe glyph names and renders SVGs at the default axis location.

How It Works

Glyph Outline Extraction

The export uses skrifa to parse font outlines and convert Bezier curve commands directly into SVG path data:

OutlineBuilder methodSVG path command
move_to(x, y)M x y
line_to(x, y)L x y
quad_to(x1, y1, x, y)Q x1 y1 x y
curve_to(x1, y1, x2, y2, x, y)C x1 y1 x2 y2 x y
close()Z

Both TrueType (glyf) and OpenType/CFF outlines are supported transparently by skrifa.

Codepoint Resolution

The export builds a reverse character map (GlyphId → char) by probing codepoints in the ranges defined by FontFamilyConfig::CODEPOINT_RANGES:

  • BMP_RANGE - U+0000–U+FFFF (default, most fonts)
  • ASCII_PRINTABLE_RANGE - U+0020–U+007E (barcode, segment fonts)
  • PUA_RANGE - U+E000–U+F8FF (icon fonts, SMuFL)
  • SUPPLEMENTARY_PUA_RANGE - U+F0001–U+10FFFF (Nerd Fonts)

Name Normalization

Glyph names from the font’s post/CFF tables are normalized to GTK-friendly icon names:

  1. Lowercase
  2. Replace _ with -
  3. Replace non-alphanumeric characters (except -) with -
  4. Collapse consecutive -
  5. Strip leading/trailing -
  6. Prefix with {glyph_name_prefix}- (e.g. doto-, dseg7-)

For Nerd Fonts, the prefix is nf- and the suffix -symbolic is added.

Empty Glyphs

Some glyphs (e.g. nonmarkingreturn, blank) have no outline data. These are exported as minimal empty SVGs so their icon names remain registered in metadata.json.

SVG Post-Processing

SvgDirSource accepts post_process hooks (SvgPostProcessor) that transform each SVG before it is written. Built-in processors include Optimize, NormalizeViewBox, CurrentColor, StripEntityNamespaces and SymbolicClasses.

SymbolicClasses matters for stroke-based icon sets (Lucide, Tabler outline): GTK’s symbolic recoloring ignores fill/stroke attributes - without classes every shape is filled with the foreground color and *-symbolic icons render as solid blobs. The processor maps effective paints onto transparent-fill / foreground-fill / foreground-stroke classes (requires GTK ≥ 4.20 for strokes). See fonts-rs-generator for the mapping table.

Font Loading

The fonts module (enabled with the render feature) handles loading font files for use with pixel-drawing or other software rendering via ab_glyph.

impl_font_loader! Macro

Each font family crate uses the impl_font_loader! macro from fonts-rs-generator to generate a cached font loading function:

#![allow(unused)]
fn main() {
// Literal: relative to resources/
fonts_rs_generator::impl_font_loader!("Doto.ttf");

// Env var: absolute path set by build.rs via cargo:rustc-env
fonts_rs_generator::impl_font_loader!(env: "DOTO_FONT_PATH");
}

The macro generates a font() -> Option<&'static ab_glyph::FontVec> function that loads the TTF font file and caches it in a OnceLock. Subsequent calls return a reference to the cached FontVec.

Loading Modes

Embedded Fonts (embed-fonts feature)

Font files are compiled into the binary via include_bytes!:

#![allow(unused)]
fn main() {
// No runtime file access needed
fonts_rs_doto::fonts::font(); // Returns Option<&'static FontVec>
}

From Disk (default)

Fonts are loaded from a path set by build.rs via cargo:rustc-env. The impl_font_loader!(env: ...) variant reads the path from the environment variable at runtime.

Caching

Fonts are loaded once and cached in a OnceLock. Subsequent calls return a reference to the cached FontVec:

#![allow(unused)]
fn main() {
use fonts_rs_doto::fonts::font;

let font1 = font().unwrap();
let font2 = font().unwrap();
assert!(core::ptr::eq(font1 as *const _, font2 as *const _));
}

Nerd Fonts (nerd-fonts-rs)

The nerd-fonts-rs crate provides additional font loading for Nerd Fonts specifically:

  1. Nerd Font (SymbolsNerdFont-Regular.ttf) - TTF file for rendering Nerd Font icons
  2. Label Font (JetBrainsMonoNLNerdFont-Regular.woff2) - WOFF2 file decompressed to TTF at load time for text labels

The label font is stored as WOFF2. The convert_woff2 function decompresses it to TTF using the woff2-patched crate. If decompression fails, it falls back to parsing the data directly as TTF.

CSS Generation

The css module provides CSS string constants for GTK and web usage.

GTK Font-Face CSS

The font_face_css() function generates a version-adapted @font-face CSS string at runtime. It detects the GTK4 library version and adjusts the src descriptor syntax for compatibility:

  • GTK >= 4.10: emits src: url("...") format("truetype") for better spec compliance with the new GtkCssParser.
  • GTK < 4.10: emits src: url("...") without a format() hint to avoid parse errors with the legacy parser.

It is loaded automatically by init() when the gtk feature is enabled.

#![allow(unused)]
fn main() {
use nerd_fonts_rs::css::font_face_css;

let css = font_face_css();
// The CSS references GResource URLs:
// resource:///io/smearor/nerd_fonts/SymbolsNerdFont-Regular.ttf
// resource:///io/smearor/nerd_fonts/SymbolsNerdFontMono-Regular.ttf
}

The CSS defines:

  • @font-face for NerdFontsSymbolsOnly (proportional)
  • @font-face for NerdFontsSymbolsOnlyMono (monospace)
  • .nerd-icon class for proportional icons
  • .nerd-icon-mono class for monospace icons

The static FONT_FACE_CSS constant retains the baseline CSS (without format() hints) for backward compatibility and testing.

Runtime Version Detection

The GtkVersion struct wraps the runtime GTK4 version and provides comparison helpers:

#![allow(unused)]
fn main() {
use nerd_fonts_rs::css::GtkVersion;

#[cfg(feature = "gtk")]
let version = GtkVersion::runtime();

let legacy = GtkVersion::new(4, 8, 0);
assert!(!legacy.at_least(4, 10));

let modern = GtkVersion::new(4, 14, 2);
assert!(modern.at_least(4, 10));
}

The GRESOURCE_PREFIX constant defines where font files are registered in the GResource system:

#![allow(unused)]
fn main() {
use nerd_fonts_rs::css::GRESOURCE_PREFIX;

fn main() {
    // Register GResource + load font (call once at startup)
    Doto::install().unwrap();

    // Now GTK can resolve icon names from the GResource bundle
    let image = gtk4::Image::from_icon_name("doto-a");
}

install() registers the compiled GResource binary containing all SVG glyph files and loads the TTF into the fontconfig/pango font map. Registration is lazy and idempotent - ensure_registered() is called automatically by glyph accessors, so install() is only needed for explicit fail-fast setup at startup.

Nerd Fonts (nerd-fonts-rs)

The nerd-fonts-rs crate provides additional GTK4 functionality:

Initialization

Call init() once at application startup:

fn main() {
    nerd_fonts_rs::init().unwrap();
    // ...
}

init() performs the following:

  1. Font initialization (with render feature) - Sets the font search base directory
  2. GResource registration - Registers the compiled GResource binary
  3. Icon registration - Registers vendored Nerd Font SVG icons
  4. CSS loading - Loads version-adapted @font-face CSS via font_face_css() into a CssProvider and adds it to the default display

GTK Icon Name Resolution

#![allow(unused)]
fn main() {
use nerd_fonts_rs::gtk::resolve_gtk_nerd_icon;

let icon_name = resolve_gtk_nerd_icon("nf-fa-gamepad");
// Returns "nf-fa-gamepad-symbolic"

let image = gtk4::Image::from_icon_name(&icon_name.unwrap());
}

The function normalizes CSS class names (like nf-fa-gamepad or fa-gamepad) into GTK icon names that gtk4::Image::from_icon_name understands.

Cheat Sheet Apps

Every font family ships a per-family *-cheat-sheet binary - nine in total. They are thin wrappers around the shared fonts-rs-cheat-sheet crate and only differ in their CheatSheetFamily type parameter:

fn main() -> miette::Result<()> {
    fonts_rs_cheat_sheet::run::<fonts_rs_lucide::Lucide>()
}

All UI behavior - grid, search, history, sidebars, toasts - is generic over F: CheatSheetFamily and lives in fonts-rs-cheat-sheet.

The application is built on libadwaita (not plain GTK4). The widget hierarchy inside build_ui:

NavigationSplitView (browse ↔ detail)

The browse grid and the detail page are the two panes of a NavigationSplitView. An adw::Breakpoint (max-width: 800sp) collapses the split view so the detail page covers the grid on narrow windows; its own HeaderBar then shows an automatic back button plus a manual close button. Window controls are suppressed on the detail HeaderBar (show_start/end_title_buttons(false)) so they are not duplicated.

OverlaySplitView (category sidebar ↔ grid)

Inside the browse page, an adw::OverlaySplitView (sidebar_position = Start) carries the navigation sidebar. It is revealed at startup and toggled by a ToggleButton in the main HeaderBar, bound bidirectionally to show-sidebar. The sidebar is omitted entirely when a family exposes neither ordering() groups nor categories.

Sidebar content is a sectioned list in one ScrolledWindow:

  • Groups - one row per group_labels() entry. Rows route through DropDown::set_selected, so active_group + grid re-render share a single code path; re-activating the selected group resets to “All groups”.
  • Categories - "{category} ({count})" rows, collected once into a BTreeMap over all_glyphs(). Click replaces the search text, Shift+click appends (space-separated AND), clicking the active row clears back to the full grid. Category pill clicks (cat-btn on grid cells and the detail page) reveal the sidebar when collapsed.

ToastOverlay (copy feedback)

Every copy action shows an adw::Toast with per-action wording - “Copied name” / “Copied character” / “Copied SVG” / “Copied codepoint” in the detail view, plus “Copied name” on secondary-click of a grid cell. The overlay is shared through DetailContext::toasts.

Ordering-Driven Grid Behavior

When CheatSheetFamily::ordering() returns a GlyphOrdering, the browse grid gains three behaviors:

  • Sort - glyphs order by order_index; variants resolve through base_of so each variant sits next to its base. Families without ordering stay alphabetical.
  • Group filter - the top-bar DropDown (mirrored by the sidebar “Groups” section) restricts the grid to group(name) == label; “All groups” clears it.
  • Variant collapsing - with collapse_variants() == true a variant is hidden in “All groups” whenever its base is visible (emoji tones, dicefont d6 styles, cuernavaca pieces). Style families (line-awesome, fluent, eva, heroicons) return false - their variants stay visible; the base_of/alternates link then only powers the detail sidebar’s Variants section and sorting.

Search- and History Model

  • The search Entry (primary edit-find-symbolic icon, secondary clear icon) filters the grid; every change pushes a HistoryEntry::Search onto the back/forward stack, so Back/Forward restore previous filters.
  • Selecting a glyph pushes HistoryEntry::Icon and shows the detail page; navigate_to restores either kind of entry.
  • suppress_history prevents loop-pushing while navigating history.

Styling

Custom CSS is intentionally thin - cell sizing, metadata pills (cat-btn/kw-btn), and hover/selected states use adwaita palette variables (alpha(@accent_bg_color, …), @success_bg_color, @warning_bg_color). Sidebar theming, dark mode, and focus styles come from the adwaita stylesheet via adw::StyleManager.

Web CSS

The web module (enabled with the web feature) provides a CSS constant for web-based widget rendering.

WEB_NERDFONT_CSS

The WEB_NERDFONT_CSS constant contains a complete CSS stylesheet with:

  • @font-face rules for loading Nerd Font symbol fonts
  • Per-icon content: "\XXXX" mappings for use in web widgets
#![allow(unused)]
fn main() {
use nerd_fonts_rs::web::WEB_NERDFONT_CSS;

// Include in your web HTML
let html = format!(
    "<style>{}</style><span class='nf-fa-gamepad'></span>",
    WEB_NERDFONT_CSS
);
}

Usage with Web Instances

The web CSS is designed for web-based widget rendering systems that display Nerd Font icons in HTML pages. Each icon class maps to its Unicode codepoint via the CSS content property.

Example HTML

<link rel="stylesheet" href="nerdfont.css">
<span class="nerd-icon nf-fa-gamepad"></span>

The CSS is generated from the SymbolsNerdFont-Regular.ttf glyph table and includes mappings for all Nerd Font symbols.

Platform Notes

Linux

Linux is the primary target for the gtk feature.

System Dependencies

# Ubuntu/Debian
sudo apt-get install -y pkg-config libgtk-4-dev libglib2.0-dev

# Fedora
sudo dnf install -y pkg-config gtk4-devel glib2-devel

# Arch Linux
sudo pacman -S pkgconf gtk4 glib2

GResource Compilation

The build.rs script uses glib_build_tools::compile_resources to compile the GResource XML into a binary. This requires glib-build-tools as a build dependency and the GTK 4 development headers to be installed.

macOS

The gtk feature can be used on macOS with GTK 4 installed via Homebrew:

brew install gtk4

No additional configuration is needed beyond the standard Rust build process.

Windows

The gtk feature can be used on Windows with GTK 4 installed via MSYS2 or gvsbuild. See the GTK4 Windows installation guide for details.

Font Loading Mode

The render feature enables font loading (TTF/WOFF2) via ab_glyph. It has no platform-specific dependencies and works on any platform supported by Rust.

[dependencies]
nerd-fonts-rs = { version = "0.5", default-features = false, features = ["render"] }

Web-Only Mode

The web feature has no platform-specific dependencies. It simply provides a CSS string constant.

[dependencies]
nerd-fonts-rs = { version = "0.5", default-features = false, features = ["web"] }

Embedded Fonts

The embed-fonts feature compiles font files directly into the binary. This increases binary size by approximately 200-500 KB but eliminates the need for runtime file access. This is useful for:

  • Standalone binaries
  • Environments without a filesystem
  • Simplified deployment
