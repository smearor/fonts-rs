# Upstream Sourcing

Every crate that vendors files from an upstream project declares its
sources in `upstream.toml` and records the resolved result in
`upstream.lock`, both committed next to `resources/`. The `xtask`
helper crate provides three commands to work with them:

```bash
cargo xtask sync -p <crate>     # populate/refresh resources/
cargo xtask check [-p <crate>]  # report upstream drift
cargo xtask verify [-p <crate>] # re-hash committed resources
```

**Vendored artifacts stay in git.** Builds never touch the network -
`xtask` *writes* `resources/`; reproducibility means "re-derivable on
demand", not "fetched at build time".

## `upstream.toml`

The sourcing manifest of a vendored crate. It has three sections; all
paths are relative and must not escape the crate/checkout (`..` and
absolute paths are rejected). Targets must be unique across license,
artifacts and metadata.

### `[upstream]` - git source (optional)

Crates sourced purely from `url` artifacts omit this section entirely.

```toml
[upstream]
repo = "tailwindlabs/heroicons"        # owner/name shorthand or full git URL
ref = "v2.2.0"                         # tag, branch or commit SHA

[upstream.license]                     # optional
source = "LICENSE"                     # path inside the upstream checkout
target = "resources/LICENSE"           # vendored path below the crate dir

sparse = [                             # optional, extra checkout paths
  "icons/*.json",                      # for provider inputs not covered
  "categories/*.json",                 # by artifact/license sources
]
```

The checkout itself is sparse and content-cached: `xtask` resolves the
ref via `git ls-remote`, then fetches with `--depth 1 --filter=blob:none`
into `~/.cache/fonts-rs/upstream/<repo>/<commit>` with a `--no-cone`
sparse checkout covering only the paths the manifest needs. The first
path component of every `source` (artifacts and license) is included
automatically; add `sparse` only for extra inputs providers read from
the checkout (e.g. per-icon JSON metadata).

### `[[artifacts]]` - file copies

```toml
# Directory copy, glob-filtered:
[[artifacts]]
source = "optimized/24/outline"        # dir or file inside the checkout
target = "resources/svg/outline"       # dir for globs, file for 1:1 copies
pattern = "*.svg"                      # optional, default "**/*"
exclude = ["hidden-icon.svg"]          # optional curated exclusions

# URL fetch (no checkout needed; mutually exclusive with `source`):
[[artifacts]]
url = "https://raw.githubusercontent.com/google/fonts/bd8f81d/.../OFL.txt"
target = "resources/LICENSE.txt"
```

- **`source`** - a file inside the upstream checkout for 1:1 copies, or
  a directory scanned recursively against `pattern`. Mutually exclusive
  with `url`.
- **`url`** - an external URL fetched verbatim at sync time (release
  assets, pinned raw-file URLs, API endpoints). `pattern`/`exclude` do
  not apply. Pin immutable URLs: release assets, commit-SHA paths,
  versioned CDN URLs - anything mutable will fail `verify` silently
  later.
- **`pattern`** - glob relative to `source` (e.g. `**/*.svg`). Matched
  files are flattened into `target` by basename.
- **`exclude`** - globs skipped even when `pattern` matches (curated
  exclusions, e.g. icons intentionally not in the set).

### `[[metadata]]` - provider-generated files

```toml
[[metadata]]
provider = "iconify_aliases"
output = "resources/metadata/aliases.json"
with.iconify_set = "heroicons"
with.suffixes = ["-16-solid", "-20-solid", "-solid"]
```

A provider generates file content from the upstream checkout and/or
fetched external inputs, driven by its `with.*` parameters. Registered
providers:

| Provider | `with.*` parameters | Generates |
|----------|---------------------|-----------|
| `copy` | `source` | verbatim copy of one checkout file |
| `eva_metadata` | `source` | name/tag metadata from an upstream file |
| `heroicons_keywords` | `site` (optional, default `https://heroicons.com`) | search keywords extracted from the site JS bundle |
| `iconify_aliases` | `iconify_set`, `suffixes`, `version` (optional) | v1→v2 style alias map from iconify's `icons.json` |
| `line_awesome_aliases` | - | FA4/FA5 compatibility aliases from LA stylesheets |
| `line_awesome_codepoints` | - | `$la-{name}: \fXXX` codepoint map from `_variables.scss` |
| `lucide_metadata` | `source`, `fields` | merged per-icon metadata from a JSON directory |

## `upstream.lock`

Generated by `sync` - never edited by hand. Records the resolved
upstream coordinates plus the SHA-256 of every vendored file:

```toml
[upstream]
repo = "tailwindlabs/heroicons"
ref = "v2.2.0"
commit = "616b7a4dbbf3d011760af8066262cd5c6b3868f3"

[[artifacts]]
target = "resources/svg/outline/academic-cap.svg"
sha256 = "…"
source = "optimized/24/outline/academic-cap.svg"

[[inputs]]
url = "https://unpkg.com/@iconify-json/heroicons@1/icons.json"
sha256 = "…"
provider = "iconify_aliases"
```

- **`[upstream]`** - absent for URL-only manifests. `commit` is the
  resolved SHA; `ref` is the manifest pin that produced it.
- **`[[artifacts]]`** - every vendored file: `target` (crate-relative),
  `sha256` (content), `source` (checkout path or `provider:<name>`).
- **`[[inputs]]`** - external non-git inputs fetched by providers
  (`url` + `sha256` + `provider`), recorded for provenance.

## Resource crates

Vendored payloads can live in dedicated *resource crates* so several
crates share them (or so a large payload is split under the crates.io
10 MiB limit - the emoji families do exactly this). A resource crate
declares a unique `links` key and emits directory paths from its
`build.rs`:

```toml
# fonts-rs-blobmoji-glyphs/Cargo.toml
links = "blobmoji_glyphs"
```

```rust
// fonts-rs-blobmoji-glyphs/build.rs
println!("cargo:svg_dir={}", manifest_dir.join("resources/svg").display());
println!("cargo::rerun-if-changed=resources");
```

Cargo exposes each `cargo:<key>=<value>` line to dependents'
`build.rs` as `DEP_<LINKS>_<KEY>` (`DEP_BLOBMOJI_GLYPHS_SVG_DIR` here).
Two rules matter:

- **`DEP_*` only flows along `[dependencies]` edges.** Resource crates
  must be declared as normal dependencies of the crate whose
  `build.rs` consumes the variable - declaring them under
  `[build-dependencies]` yields an unset variable.
- **A `links` crate still needs a lib target** - a stub `src/lib.rs`
  suffices; the crate carries no runtime API.

Resource crates vendored from upstream carry their own
`upstream.toml`/`upstream.lock` with disjoint `pattern`/`exclude`
slices of the upstream tree - e.g. `fonts-rs-blobmoji-glyphs` pins
`emoji_u*.svg` minus `emoji_u*_*`, `fonts-rs-blobmoji-sequences` pins
`emoji_u*_*`. `verify` and `check` cover them like any other vendored
crate, so the byte-exact guarantee is unchanged.

## Commands

### `cargo xtask sync -p <crate> [--update]`

Resolves the manifest pin (or, with `--update`, the newest version-like
tag / remote HEAD), materializes the sparse checkout, copies
`[[artifacts]]`, runs `[[metadata]]` providers, then writes
`upstream.lock`. Re-running `sync` on an unchanged manifest refreshes
`resources/` from the same lock coordinates - byte-identical unless
a provider's external input drifted.

### `cargo xtask check [-p <crate>] [--json]`

Reports drift without touching `resources/`: for each crate whether
the pinned ref moved upstream (new tag, HEAD advanced), whether
provider inputs changed (bundle re-fetched and re-hashed), and any
fetch errors. `--json` emits a machine-readable report. Without `-p`,
checks every vendored crate and prints an aggregate report. A weekly
scheduled CI job runs this check.

### `cargo xtask verify [-p <crate>]`

SHA-256s every locked file against committed `resources/` and reports
`missing`/`mismatch` by name - non-zero exit on any failure. Files in
`resources/` without a lock entry produce a warning (unknown
hand-adds) but do not fail. This runs as a gate on every pull request:
committed resources can never silently diverge from the lock.

## Bump procedure

Bumping a crate to a newer upstream is a normal review flow:

```bash
cargo xtask sync -p fonts-rs-heroicons --update   # re-pin manifest + re-vendor
git diff crates/fonts-rs-heroicons                # review resources/ + manifest + lock
cargo xtask verify -p fonts-rs-heroicons          # sanity check
cargo build -p fonts-rs-heroicons                 # rebuild generated code
```

`--update` picks the newest version-like tag when upstream releases;
otherwise it follows the remote default HEAD. Review the diff - a bump
is "commit `resources/` + `upstream.toml` + `upstream.lock`", all in
one reviewable change.

## Writing a provider

A provider is a unit-testable Rust type implementing the `Provider`
trait in `xtask/src/providers/`:

```rust
use crate::providers::Provider;
use crate::providers::ProviderContext;
use crate::providers::ProviderOutput;
use crate::providers::required_string;

/// `my_provider`: reads `with.source` from the checkout and emits JSON.
pub struct MyProvider;

impl Provider for MyProvider {
    fn name(&self) -> &'static str {
        "my_provider"
    }

    fn generate(&self, context: &ProviderContext) -> miette::Result<ProviderOutput> {
        let source = required_string(context.with, "source", self.name())?;
        let text = std::fs::read_to_string(context.checkout()?.join(source))?;
        let content = transform(text)?;
        Ok(ProviderOutput::file(content.into_bytes()))
    }
}
```

- **`ProviderContext.checkout`** - `Option<&Path>`: root of the
  upstream sparse checkout, `None` for URL-only manifests. Call
  `context.checkout()?` to require it, or source purely via `http_get`.
- **`ProviderContext.with`** - the `[[metadata]] with.*` parameter
  table (`toml::Table`). Use `required_string` /
  `required_string_list` for mandatory keys.
- **`ProviderContext.http_get(url)`** - shared per-sync HTTP fetch
  cache: one request per URL regardless of how many providers need it.
- **`ProviderOutput.content`** - the generated file written to
  `output`.
- **`ProviderOutput.inputs`** - every external URL fetched while
  generating (recorded as `[[inputs]]` in the lock). Use
  `ProviderOutput::file(content)` when there are none.

Register the provider by name in `resolve_provider` in
`xtask/src/providers/mod.rs`, and extend the registry test - the
manifest fails with "Unknown metadata provider" otherwise. Keep the
generated output deterministic (sorted maps, stable formatting) so
`verify` and `check` see real drift rather than serialization noise.
